# 平台安裝說明

這份文件只用於「第一次建立整個訂閱平台」或建立新的隔離測試平台。一般新業主不要走這套流程。

## 需要準備

- Node.js 20 以上與 npm
- Cloudflare 帳號及 Wrangler 登入
- LINE Developers Provider、Messaging API、LINE Login／LIFF
- 共用標準版與旗艦版 OA 規劃
- 一個不含真實資料的測試環境

## 安裝順序

1. 解壓安裝包到獨立資料夾。
2. 執行 `./product-kit/bin/check-system.sh`。
3. 執行 `./product-kit/bin/install-local.sh`。
   安裝包只執行可在包內獨立完成的測試；依賴內部工作紀錄或未授權 migration 0030 的開發測試不會放入商品包。
4. 複製 `backend/wrangler.template.toml` 為獨立環境設定，再填入自己的非秘密資源名稱與 ID。
5. 在 Cloudflare 建立 D1、R2、Worker 與 Pages 專案。
6. 僅執行已核准的 migration；目前一般安裝上限為 `0029`。
7. 使用 Wrangler secret 指令逐項設定 LINE／平台秘密；不要建立含真值的設定檔交付給別人。
8. 部署 Worker，確認 `/api/health`。
9. 部署 Pages，設定標準版、旗艦版與業主 LIFF endpoint。
10. 用測試 LINE 帳號完成客戶預約、業主受理、訂金確認、取消與逾期流程。

## 上線前必驗

- tenant 隔離：不同業主不可互看資料。
- LINE 身分：客戶與業主不可互換權限。
- 預約時段：重疊防呆、取消與逾期後釋放。
- 通知：新事件即時發送；cron 只作舊失敗保險與期限工作。
- 備份：D1 匯出可成功產生且檔案非空。
- secrets：程式碼、安裝包與畫面均不顯示真值。

## 不可自動化的部分

LINE OA 建立、LIFF endpoint 核准、Cloudflare secrets 與正式網域切換涉及帳號權限，必須由平台負責人確認，不應做成無確認的一鍵腳本。
